불러온 레이어가 화면 밖 엉뚱한 곳에 찍히거나, 분명 같은 지역인데 두 레이어가 서로 겹치지 않은 적 있으신가요. QGIS를 처음 쓸 때 가장 자주 막히는 지점이 바로 **좌표계**입니다. 이 글 하나면 원인을 진단하고 바로잡는 법까지 끝냅니다.

> **바쁘면 이것만**: 레이어가 안 맞으면 대개 좌표계가 "잘못 정의"된 것입니다. 데이터 좌표값은 그대로 두고 올바른 좌표계로 **다시 정의**하면 됩니다. 실제로 좌표값을 바꿔야 할 때만 **재투영(변환)**을 씁니다. 이 둘을 헷갈리는 게 최대 함정입니다.

## 좌표계란 무엇인가

좌표계(CRS, Coordinate Reference System)는 "지구 위 한 점을 숫자로 어떻게 표현할지"에 대한 약속입니다. 크게 둘로 나뉩니다.

- **지리 좌표계(경위도)**: 도(°) 단위. 예) WGS84(**EPSG:4326**). GPS와 구글 지도가 씁니다.
- **투영 좌표계(미터)**: m 단위. 거리와 면적 계산에 적합합니다. 한국에서 자주 쓰는 것:
  - **EPSG:5186** — GRS80 중부원점 TM (국가 기본도)
  - **EPSG:5179** — UTM-K (브이월드·네이버·카카오)
  - **EPSG:3857** — 웹 메르카토르 (웹 배경지도)

레이어마다 "이 데이터는 어떤 좌표계다"라는 꼬리표가 붙어 있어야 QGIS가 제 위치에 그립니다.

## 왜 안 맞을까 — 원인은 두 가지

1. **좌표계가 잘못 정의됨** (가장 흔함): `.prj` 파일이 없거나 틀려서 실제 데이터와 다른 좌표계로 표시됩니다. 엉뚱한 곳에 찍히거나 아예 안 보입니다.
2. **좌표계는 맞지만 변환이 필요함**: 다른 좌표계 기준으로 좌표값을 실제로 바꿔 내보내야 하는 경우입니다.

대부분의 "안 맞아요"는 1번입니다.

## 해결 3단계

### 1단계 — 진단: 지금 좌표계 확인

레이어 우클릭 → **속성 → 정보** 에서 현재 CRS를 봅니다. 상태표시줄 오른쪽 아래에도 프로젝트 CRS가 보입니다. 좌표값이 경위도(예: 127, 37)인데 미터 좌표계로 잡혀 있거나 그 반대면 정의가 틀린 것입니다.

> 📷 **스크린샷 ①** — 레이어 속성 정보 탭에서 현재 좌표계 확인
> _최종본 alt·캡션: "QGIS 레이어 속성 정보 탭에서 현재 좌표계(CRS) 확인 화면"_

### 2단계 — 정의가 틀렸다면: 올바른 좌표계로 다시 지정

레이어 우클릭 → **레이어 CRS 설정 → 레이어 좌표계 지정**. 데이터에 맞는 EPSG(예: 국가 기본도면 5186)를 고릅니다. 이 작업은 **좌표값을 바꾸지 않고 꼬리표만 고칩니다.** 올바로 지정하면 QGIS가 자동으로 제자리에 그립니다(실시간 재투영).

> 📷 **스크린샷 ②** — 좌표계 지정 대화상자에서 EPSG 검색·선택
> _최종본 alt·캡션: "QGIS에서 EPSG:5186 좌표계를 검색해 지정하는 화면"_

### 3단계 — 실제로 변환이 필요하면: 다른 이름으로 저장

좌표값 자체를 다른 좌표계로 바꿔 저장해야 할 때는 레이어 우클릭 → **내보내기 → 객체를 다른 이름으로 저장** → 대상 좌표계(CRS)를 지정합니다. 재투영된 새 파일이 생성됩니다(원본은 그대로).

> 📷 **스크린샷 ③** — 다른 이름으로 저장 시 대상 좌표계 지정
> _최종본 alt·캡션: "QGIS 객체를 다른 이름으로 저장하며 대상 좌표계로 재투영하는 화면"_

## 흔한 실수와 함정

- **정의(지정) ≠ 변환(재투영)**: "레이어 CRS 설정"은 꼬리표만 바꾸고, "다른 이름으로 저장 + CRS 지정"은 좌표값을 실제로 계산합니다. 틀린 데이터에 변환을 걸면 더 엉킵니다. 먼저 올바로 **정의**부터 하세요.
- **프로젝트 CRS와 레이어 CRS는 다릅니다**: 프로젝트 CRS는 화면 표시용이고, 각 레이어의 CRS가 그 데이터의 진실입니다.
- **`.prj` 파일 챙기기**: 셰이프파일은 `.shp`만이 아니라 `.prj`까지 있어야 좌표계가 따라옵니다.
